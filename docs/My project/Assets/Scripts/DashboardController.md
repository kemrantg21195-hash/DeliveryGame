Согласно структуре проекта (`Assets/Scripts`), файл относится к слою скриптов игровой логики и подключается к игровому объекту (GameObject) сцены через механизм Unity-компонентов.

- получает доступ к жизненному циклу Unity (`Awake`, `Start`, `Update`, `OnEnable`, `OnDisable` и т.д.);

- работает с корутинами, `UnityEvent`, а также со UI-системой (uGUI / TextMeshPro).

Назначение файла — связать модель данных о доставках (заказы, курьеры, маршруты, деньги, время, статистика) с визуальным представлением: обновлять значения, реагировать на события игры и обрабатывать действия игрока (кнопки, вкладки, фильтры).

## Описание класса `DashboardController`

### Назначение

Класс `DashboardController` реализует контроллер (часть паттерна MVC/MVVM) для панели показателей доставки. Он:

1. **Хранит ссылки на UI-элементы** — текстовые поля, слайдеры, прогресс-бары, списки заказов, иконки.
2. **Считывает данные из игровой модели** (менеджеры заказов, экономики, времени, статистики).
3. **Обновляет интерфейс** — значения, цвета, видимость панелей, анимации.
4. **Обрабатывает пользовательский ввод** — нажатия кнопок, переключение вкладок, выбор заказа.

## Взаимодействие с другими системами

Обычно `DashboardController` не содержит игровой логики, а выступает **представлением** над моделями:

```
[OrderManager] ──события──┐
[EconomyManager] ────────┼──► DashboardController ──► UI (TMP_Text, Image, Prefab-карточки)
[GameTimer] ─────────────┘
```

Он подписывается на события (например, `OrderManager.OnOrderAdded`, `EconomyManager.OnMoneyChanged`) и вызывает собственные методы обновления UI. Такой подход обеспечивает слабую связанность и упрощает тестирование.

## Примеры использования

### Пример 1. Подписка на события и обновление панели

```csharp
public class DashboardController : MonoBehaviour
{
    [SerializeField] private TMP_Text moneyText;
    [SerializeField] private TMP_Text ordersCountText;

    private void OnEnable()
    {
        EconomyManager.OnMoneyChanged += UpdateMoney;
        OrderManager.OnOrdersChanged += UpdateOrdersCount;
    }

    private void OnDisable()
    {
        EconomyManager.OnMoneyChanged -= UpdateMoney;
        OrderManager.OnOrdersChanged -= UpdateOrdersCount;
    }

    private void UpdateMoney(float amount)
    {
        moneyText.text = $"{amount:N0} ₽";
    }

    private void UpdateOrdersCount(int count)
    {
        ordersCountText.text = count.ToString();
    }
}
```

```csharp
public void UpdateOrdersList(IEnumerable<Order> orders)
{
    ClearOrdersList();

    foreach (var order in orders)
    {
        var card = Instantiate(orderCardPrefab, ordersListContent);
        card.GetComponent<OrderCardView>().Bind(order, OnOrderCardClicked);
    }

    SetStatusMessage(orders.Any() ? string.Empty : "Нет доступных заказов");
}
```

## Рекомендации по сопровождению

- **Кэшируйте ссылки** на компоненты в `Awake()`, а не ищите их в `Update()` — это снижает нагрузку.
- **Отписывайтесь от событий** в `OnDisable()`/`OnDestroy()`, иначе возможны `MissingReferenceException` и утечки.
- **Не помещайте игровую логику** в контроллер UI — разделяйте представление и модель.
- **Используйте пул объектов** для карточек заказов при высокой частоте обновлений, чтобы избежать постоянных `Instantiate`/`Destroy`.
- **Проверяйте `null`** для необязательных UI-полей: панель может использоваться в разных сценах с разным набором элементов.
